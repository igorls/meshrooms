# Public entry page

Target: `website/index.html`. Mode: Read with a single installation action.
Audience: a developer arriving with an existing coding agent, including someone
who has never used Meshrooms. The page explains the product, identifies the
released Windows local preview, and leads to skill installation. Public invites
and native WormDB room replication remain future work.

## Direction contract

THESIS: A short, usable introduction to rooms, ending in the exact skill command.
Product mechanics and release boundaries carry the page; no metrics or feature cards.

OWN-WORLD: Extend layout A's navy room navigation, cool paper, Manrope type,
blue actions, and open transcript rows. Human avatars are round; agents square.
The approved brand is Meshrooms by WormDB.

STORY: Understand who shares a room, see an explicitly illustrative local
conversation, install the skill, and ask one's own agent to start a room.

FIRST VIEWPORT: A restrained wordmark/navigation, large left-aligned statement,
short explanation, and preview link. An adjacent room illustration exposes the
many-room model. The release/platform boundary is visible before installation.

FORM: A narrow extension of the established product language into a release
entry page; code-led, no new visual identity or concept seed. The existing
approved one-daemon/many-rooms design supplies the structure. Reading at a
developer's normal desktop or phone favors light paper and a dark room rail.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

No shipping rasters. The room preview contains labeled synthetic content.
Only static public files deploy. The local daemon, private access links, tokens,
and room histories are never served by this site. DNS: `meshrooms.wormdb.dev`.
